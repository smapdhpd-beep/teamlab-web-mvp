## 二、结合 Vibe Coding，你能学到什么（用户视角）

### 1. "体感交互"不是锦上添花，而是 teamLab 的核心差异
teamLab 实体展最震撼的不是画面多美，而是"身体在场"。Step 5~6 把摄像头体感做进去后，用户从"看客"变成"参与者"。
- ** takeaway**：如果你的交互作品只支持鼠标，永远只是"演示"。让身体进来，体验立刻升维。

### 2. "有异议提出来确认再执行"是防崩盘的最后一道防线
Step 6 双手靠近时，我如果直接按用户原始方案写，MediaPipe 返回不完整 landmarks 会导致画面冻结。但我提前提了 7 条异议，其中"Hand ID 索引不稳定"和"坐标映射"的防御性检查直接避免了后续 Bug。
- **takeaway**：AI 写代码快，但视觉/体感相关的代码很容易因为硬件/浏览器/API 边界情况崩溃。要求 AI"有异议先提"，是花 2 分钟省 2 小时调试的关键仪式。

### 3. 防御性编程比完美方案更重要
Step 6 的 Bugfix 不是优化，是救命。`landmarks[8]` 为 undefined 时，崩溃的不只是一个函数，而是整个 `draw()` 循环 + MediaPipe 回调链。
- **takeaway**：任何外部 API（摄像头、传感器、网络）返回的数据都必须做"脏数据过滤"。不要假设 API 永远给你完整结构，要假设它随时会给你一个空数组或 undefined。

### 4. "柔软"来自分层，不是单一参数
Step 6 的光晕调了三次：单圆 → 同心圆 → 径向渐变 + 呼吸。每次调优都不是"改一个数字"，而是**换一层实现架构**。
- **takeaway**：如果调参数调了三次还不满意，不要继续调，要换实现方式。从几何硬边 → 多层叠加 → 数学渐变，是质的跃迁。

### 5. 性能优化要卡在数据结构的根上
Step 8 的光之网如果暴力 O(n²)，1500 粒子要算 112 万次距离。但用 50×50 网格 + Map 存储 + 只查 9 格，降到约 12 万次。
- **takeaway**：不要先写循环再优化。在写循环之前，先问"这些元素的空间关系是什么？"空间索引（网格、四叉树、哈希）是 Canvas 交互的必修课。

### 6. 颜色管理要有"纪律"，否则画面会脏
Step 8 如果只按距离连线，粉色和青色粒子之间会产生大量灰紫色脏线。通过 `colorType` 强制同色连线，画面反而更有层次（粉网、青网、金网交织）。
- **takeaway**：随机混合颜色 ≠ 丰富。有节制的分组 + 组内连接，比无差别全连接更有高级感。teamLab 的作品里，颜色是分"族群"的。

### 7.  blendMode 是视觉层级的骨架，不是装饰
今天的渲染顺序从 Step 3 的 3 层，发展到 Step 8 的 6 层：
```
BLEND → background → 波纹 → 连线 → ADD → 光晕 → 粒子 → BLEND → UI
```
每一层在什么混合模式下绘制，决定了它会不会过曝、会不会被遮挡、会不会和上层打架。
- **takeaway**：做发光/粒子/后处理效果时，先画好 blendMode 架构图，再填内容。顺序错了，调参数调到死也出不了效果。

### 8. 把参数暴露为 CONFIG，调优时只看一个地方
今天所有手感参数（repelStrength、EMA α、光晕半径、波纹力度）都集中在 `main.js` 顶部的 `CONFIG`/`HAND_CONFIG`/`RIPPLE_CONFIG` 对象里。
- **takeaway**：vibe coding 容易陷入"改代码→刷新→不满意→再改"的循环。把所有"可能今天改十遍"的变量提到顶部，刷新即见效，不用在文件里翻找。
