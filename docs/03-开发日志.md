## Step 9 — 流动场 / Flow Field（2026-06-22）

**任务类型**：核心体验升级（有机运动）
**触发信号**：用户确认全部 7 条技术异议，指令"按规范写入"，验收通过

### 做了什么
- 新建 `js/flowfield.js`：`FlowField` 类
  - `Float32Array` 一维化存储：`this.field = new Float32Array(cols * rows)`，按 `idx = row * cols + col` 索引，避免每帧重建二维数组的 GC 压力
  - `update()`：双层循环生成 Perlin 噪声角度场，`zoff += 0.003` 实现时间维度缓慢演进
  - **交互扰动在场层完成**：遍历网格中心点，若与 `window.interactPos` 距离 <100px，角度 `+= map(d, 0, 100, HALF_PI, 0)`，下一帧 noise() 自然覆盖消散
  - `getForce(x, y)`：双线性插值（bilinear interpolation），取周围 4 格点按 sub-grid 坐标加权，消除最近邻跳变
  - `display()`：调试用箭头可视化，按 D 键切换
- `js/particles.js`：
  - constructor 拆分 `baseSpeed = random(0.3, 0.7)`（一次性）与 `baseVel = random2D().mult(baseSpeed)`
  - `update()` 末尾：读取 `window.flowField.getForce()`，方向 `lerp(0.05)` 缓慢转向，速率 `normalize().mult(baseSpeed)` 保持不变
- `js/sketch.js`：
  - `setup()` 初始化 `window.flowField = new FlowField()`
  - `draw()` 仲裁后暴露 `window.interactPos = interactPos || window.mousePos || null`
  - 渲染顺序：`background()` 之后调用 `flowField.update()`，场先于粒子更新
  - `keyPressed('d')` 切换 `window.showFlowField`，在 UI 层前绘制调试箭头
  - `monitorPerformance`：FPS<30 时 `FLOW_CONFIG.resolution *= 1.5`（上限 80px），调用 `flowField.onResize()` 重建
- `js/main.js`：新增 `FLOW_CONFIG`（resolution / noiseScale / timeSpeed）
- `index.html`：引入 `js/flowfield.js`

### 关键决策
- **方向与速率通道拆分**：`baseVel` 负责方向（被 flowField 缓慢改变），`baseSpeed` 负责大小（个体恒定），避免每帧 random 导致速度大小高频抖动
- **扰动在场更新层而非 getForce**：保持查询函数只读，避免每粒子重复计算与交互点距离
- **双线性插值必须**：`floor(col)` 跳变会让粒子轨迹出现周期性折线，lerp 本身无法掩盖底层采样不平滑
- **性能自适应联动**：resolution 从 20px 开始，卡顿自动升到 30px→45px→67px→80px，与粒子降级并行

### 文件改动清单

## Step 10 — Bloom 后处理辉光（2026-06-22）

**任务类型**：视觉收官（屏幕空间弥散）
**触发信号**：用户确认全部 7 条技术异议，指令"按规范写入"，"效果和互动都没问题"

### 做了什么
- 新建 `js/bloom.js`：`Bloom` 类
  - `ctx.filter` 支持性检测：不支持则 `enabled = false`，避免旧浏览器 fallback 到纯 JS 像素遍历导致帧率暴跌
  - `createGraphics(width/4, height/4)` 逻辑尺寸降采样（异议 1），非 `pixelDensity(0.5)`
  - `render()`：纯黑背景 `background(0)`（异议 2），避免 `clear()` + `filter(BLUR)` 产生半透明脏雾
  - 只画粒子发光部分（异议 3），不重复绘制吸引光晕
  - 无硬阈值，按 `150 * p.lifeAlpha` 平滑衰减（异议 4）
  - 坐标与尺寸按 `scale` 缩放（异议 7）
  - `display()`：通过 `tint(255, 255 * BLOOM_CONFIG.strength)` 控制叠加透明度
- `js/particles.js`：核心 alpha 让渡，`120→80`、靠近时 `180→120`（异议 6）
- `js/sketch.js`：
  - 渲染顺序：`bloom.render(particles)` 在连线后（读取本帧粒子状态），`bloom.display()` 在粒子循环后（ADD 叠加）
  - `keyPressed('b')` 切换 Bloom 开关
  - `monitorPerformance`：FPS<30 自动 `bloom.enabled = false`
  - `windowResized` 同步 `bloom.onResize()`
- `js/main.js`：新增 `BLOOM_CONFIG`（enabled / scale / radius / strength）
- `index.html`：引入 `bloom.js`

### 关键决策
- **亮度让渡策略**：粒子核心 alpha 从 120 降到 80，把"高亮感"让渡给 Bloom 层负责，避免主画布 ADD + Bloom ADD 双重叠加导致死白
- **黑背景是 Bloom 层的灵魂**：透明背景 + blur 会产生灰色羽化雾，黑色背景则只扩散发光边缘，ADD 叠加后画面保持深邃
- **ctx.filter 检测是性能底线**：旧版 Safari 不支持 `ctx.filter`，p5.js 会 fallback 到 CPU 卷积，1500 粒子下帧率会崩到个位数
- **1/4 分辨率是性能与效果的平衡点**：radius 20 在 1/4 画布上等效 5px 模糊，放大后视觉半径约 20px，足够产生弥散感，同时大幅降低 `filter()` 开销
