# 项目概述

## 核心定位

teamalb-web-mvp 是一个**实时生成的交互粒子艺术网页**。它不播放预录视频，也不跑固定动画，而是每一帧都在实时计算：粒子飘向哪里、 mouse 靠近时怎么散开、什么时候诞生、什么时候消逝。这意味着两个人打开同一个页面，看到的画面永远不会完全一样。

我们的目标不是"复刻 teamLab"，而是抓住 teamLab 最核心的三个体验：
1. **去边界感** — 粒子走出画面会从另一边进来，你永远看不到尽头
2. **实时生成** — 画面不是放电影，是"长"出来的
3. **有机生灭** — 粒子会死，也会新生，像一片活的草地

## 技术选型理由

**为什么用 p5.js？**

因为它让画布操作变得像说话一样简单。`circle(x, y, r)`、`random()`、`map()` — 这些直觉式的 API 让我们可以把精力花在"粒子该怎么感受鼠标"而不是"WebGL 着色器怎么写"。如果将来需要更重的后处理，再往上叠 WebGL 也不迟。

**为什么不用框架（React/Vue）？**

这个项目没有状态管理、没有路由、没有组件嵌套。一个 HTML 文件 + 几个 JS 模块就够了。框架只会增加构建步骤和认知负担。

**为什么粒子数 1500？**

试出来的。1000 个有点稀，2000 个低端电脑会卡。1500 是"看起来足够密"和"大部分设备跑得动"之间的平衡点。移动端自动砍半到 500。

## 设计哲学

### 去边界

粒子走出左边界，从右边界回来；走出上边界，从下边界回来。画布不是窗户，是卷轴。用户永远不会被边框提醒"这是一个屏幕里的程序"。

### 柔和交互

粒子的排斥不是"弹开"，而是"被水流推开"。我们给每个粒子保留了"基础漂移速度"，交互产生的额外速度会慢慢衰减回去。鼠标移走后，粒子不会突然复位，而是像受惯性的水草一样缓缓归位。

### 有机生灭

粒子不是永恒存在的。它们出生（淡入）、成长、衰老、死亡（淡出），然后新的粒子在某个角落悄悄诞生。整体数量保持恒定，但每个个体都在流转。这让画面有了呼吸感，而不是机械循环。

### 亮度克制

发光效果很容易过曝，刺得人眼疼。我们刻意压低了光晕层数和核心亮度，让画面可以长时间观看而不疲劳。teamLab 的作品之所以能挂在美术馆里让人站很久，部分原因就是它们不刺眼。
